# Modules baked into the AMIRA images by the overlay: compose.amira.yml sets the
# EXTRA_MODULES_FILE build arg to this file, which the Dockerfile reads in
# addition to _docker/default-modules.txt (same omeka-s-cli syntax).
#
# Everything AMIRA-specific belongs here rather than in _docker/extra-modules.txt
# so the generic base stack partners build from stays free of it.
#
# A plain .zip URL makes omeka-s-cli unpack that published release archive; a
# gh: line makes it clone the repository at a branch or tag, development tree
# and git history included. Prefer the release archive where one exists.
# scripts/update-module.sh rewrites the tag in these URLs to the newest release.
https://github.com/AM-Digital-Research-Environment/DRESearch/releases/download/v1.20.1/DRESearch.zip
https://github.com/AM-Digital-Research-Environment/DRE-SEO/releases/download/v0.9.0/DRESeo.zip
# The repository is DRE-Visualizations; the archive it publishes, and so the
# module folder it unpacks to, is DreVisualizations — the name compose.amira.yml
# mounts the precomputed-artifact volume at.
https://github.com/AM-Digital-Research-Environment/DRE-Visualizations/releases/download/v2.28.1/DreVisualizations.zip
